## Data left in Latin script / formatting decisions

- **`bdi` not possible** — `window.confirm` prompts, `<Modal title aria-label>` strings and toast state strings cannot carry markup, so staff/branch **names inside those sentences are not wrapped in `<bdi dir="ltr">`** (`staff.confirm_reset`, `confirm_deactivate`, `confirm_reactivate`, `notice_*`, `modal_edit_title`, `branches.error_duplicate_code`). Everything rendered inside JSX text is wrapped.
- **Server text still shown** — `DataExportScreen` shows the export job's own `error_message` verbatim (it is a job field, not an API `detail`). Staff/Branches/Tenant/Catalog API errors go through `messageForError` when the error carries a `code`; without a code the local translated key is used.
- **StaffScreen exception** — a non-`ApiError` `Error` still renders `err.message`, because `__tests__/staff/StaffScreen.test.tsx` asserts the backend's `role_not_enabled` sentence. Real API failures arrive as `ApiError` and are translated; only programming/test errors keep their raw text. This is the one place the "never render server detail" rule is knowingly bent to keep an existing test green.
- **Audit timestamp** — `DetailPanel` still uses `new Date(...).toLocaleString()`; `formatDateTime` would change the displayed format, so I left it (rule 9 escape hatch).
- **Export "Requested" timestamp** — `DataExportScreen` still uses `toLocaleString("en-GB")`; switching to `formatDateTime` would change the visible format (e.g. `13/11/2026, 17:49:26` → `13 Nov 2026, 17:49`), so I left it. Worth standardising in a follow-up.
- **Money** — the only amount on these screens is the panel package price, now rendered with `formatMoney` (`PKR 2200.00` in English, `روپے 2200.00` in Urdu).
- **Department / category values in tables** — the stored `category` string is shown as returned (English). Only the fixed filter pills and select options are translated.
- **Whole-cell LTR** — reference-range bounds, critical bounds and effective dates are wrapped in `dir="ltr"` spans instead of per-token `<bdi>`; the `→` in "from → to" is therefore not mirrored.
- **Placeholders** — hex example `#005C55`, TOTP `000000`, `name@lab.pk` and unit/price examples stay Latin (data / format hints).
