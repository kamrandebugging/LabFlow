## Notes that are not translation uncertainty

- **Date format changed (intentional).** The five screens used
  `new Date(value).toLocaleDateString()` inline. They now use
  `formatDate()` from `lib/format.ts`, so the output is `20 Oct 2026`
  (English month names, Doc 07 §10) instead of a browser-locale string such as
  `10/20/2026`. No existing patients test asserts the old format; this is
  flagged here because it is a visible change in English too.
- **`formatAge` was deliberately not used** in the list screen. Its bands
  (days/months/years) would change today's always-in-years output for infants,
  and the screen also falls back to `year_of_birth` when no DOB exists, which
  `formatAge` cannot express. The existing age calculation is unchanged; only
  the unit word is translated (`patients:list.age_years`).
- **Error text no longer shows `err.message`.** Server detail is replaced by
  `messageForError(err, t)` when the error carries a `code`/`status`, otherwise
  by a translated fallback key. `patientService` wraps `ApiError` into a plain
  `Error` for `getPatient`/`updatePatient`/`deletePatient`, so those paths show
  the translated fallback rather than a developer message.
- **`window.confirm` / `alert` were kept** (no UI change) but now receive
  translated text.
- **Attribute-only strings carry no `<bdi>`.** Placeholders, `aria-label`s and
  `title`s are plain strings, so `MRN`, `accession`, `ISO 15189`, `WhatsApp` and
  the digit ranges (`10-15`, `2 سے 120`) sit inside Urdu without an isolating
  element. Single Latin tokens surrounded by Urdu and digit ranges are low-risk
  in the bidi algorithm, but a visual pass on the Urdu placeholder
  `نام، فون یا MRN سے تلاش کریں…` is worth doing.
- Untranslated on purpose (data / clinical, per glossary): patient names, MRNs,
  branch names, phone numbers, `ISO 15189`, `WhatsApp`, `SMS`, `MRN`,
  `accession`, `ID`, the `—` / `/` / `·` / `•` separators, and the digit-only
  placeholders `03001234567` and `+92 300 1234567`.
