## Deliberate decisions (not string choices)

- **Clinical data is never translated.** Test names, panel names, values, units, ranges, flag
  values, accession IDs, MRNs, patient/lab/branch/clinician names, timestamps and comments from
  the API stay exactly as returned. Latin runs inside Urdu sentences are wrapped in
  `<bdi dir="ltr">` through `<Trans>`.
- **`en/results.json` contains one marked-up value**: `approvals.reject_modal_body` keeps
  `<strong>{{patient}}</strong>` so the existing bold emphasis on the patient name is preserved.
  The rendered English text is unchanged.
- **Attributes cannot carry markup.** `aria-label` and `placeholder` keys hold plain strings, so
  Latin terms inside them are not isolated (e.g. `entry.value_aria`, `amend.reason_placeholder`).
- **Dates/times stay inline-formatted** (`new Date(...).toLocaleString(...)`), exactly as before.
  Migrating them to `formatDateTime` from `lib/format.ts` would change the visible format from
  "Oct 20, 2026, 09:38" to "20 Oct 2026, 09:38", so per the brief it was left alone and noted
  here instead. `formatAge` does not apply: these screens show `patient_age_years` (a number),
  not a date of birth.
- **Audit-trail `status` values** in the amendment chain are rendered verbatim from the API
  (`approved`, `entered`, …). They are audit data, not UI copy.
- **API errors** never print `detail`: `ApiError` goes through `messageForError`, anything else
  falls back to a translated screen key (which keeps the original English wording, so the
  existing error tests still assert the same text).
