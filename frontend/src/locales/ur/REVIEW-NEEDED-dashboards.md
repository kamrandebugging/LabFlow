## Notes that are not translation uncertainty

- **`formatPkr` now takes a language.** `formatPkr(value, "en")` still returns
  `PKR 1250.00`; `formatPkr(value, "ur")` returns `روپے 1250.00`. The amount is
  the same `toFixed(2)` string, never regrouped. All three call sites pass
  `i18n.resolvedLanguage === "ur" ? "ur" : "en"`. `PKT_LABEL` is kept exported
  for English but is no longer read by any screen.
- **The date line moved into `DashboardUI`.** New `DashboardDateLine` renders
  `<bdi dir="ltr">{date}</bdi> · {t("dashboard.pkt_label")}` plus an optional
  scope suffix. The visible English text is unchanged; the only structural
  change is that the date is now isolated LTR so RTL cannot re-order it. The
  Owner screen no longer memoizes the string (the day label is computed at
  render).
- **`DashboardUI` prop types widened to `ReactNode`.** `DashboardHeader.subtitle`,
  `StatCard.hint` and `Panel.subtitle` were `string`; they now accept
  `ReactNode` so `<Trans>` can place `<bdi dir="ltr">` around Latin runs
  (`accessions`, `Asia/Karachi`, money). No caller lost a valid value and no
  logic changed.
- **`<Trans>` is used for 7 strings.** Only where an Urdu sentence contains a
  Latin run: the three accession-count strings, the worklist hint and subtitle,
  the outstanding-balance hint (`PKR 1800.00`) and the Owner business footer
  (`Asia/Karachi`). English has no tags in those keys, so the English rendering
  is the same plain sentence as before.
- **`critical` is left as a bare Latin word.** The glossary requires it inside
  clinical sentences (`status.flag.critical` is already "Critical" in
  `ur/common.json`), and a single Latin word between spaces does not re-order
  under the bidi algorithm, so it is not wrapped in `<bdi>`. The same reasoning
  applies to `PKT` in the hints (precedent: `common.time.pkt`).
- **Count interpolation cannot be plural-correct.** The English keys are pinned
  byte-for-byte by `__tests__/dashboard/*` (they assert "2 late sample
  transfers" _and_ "1 failed report deliveries"), so no `_one`/`_other` suffixes
  can be added without changing English. Urdu therefore uses one plural-led
  form per count string. This is the one known grammatical defect; it is
  listed per key above.
- **Three extra "unknown count" keys.** `dashboard.counts.*_unknown` render the
  em dash when the exceptions read failed. They are separate keys because
  i18next types `count` as `number`, and passing `"—"` through `count` would not
  type-check. The displayed English is identical to before (`— late sample
transfers`).
- **Worklist status badge is now translated.** The Technician worklist used to
  print the raw API value (`received`, `in_process`). It now renders
  `status.sample.*`, i.e. "Received" / "In process" in English and موصول /
  زیر عمل in Urdu. English casing changed from the machine value to the
  canonical display word (same convention as the already-translated
  `results/WorklistScreen.tsx`). No dashboard test asserts the old value.
- **Directional arrows mirrored.** The `→` glyph in `DashboardLink` and the
  three Owner link arrows got `rtl:-scale-x-100`. No physical direction
  utilities were added; the worklist/today-registration tables were already on
  `text-start` / `pe-*` before this change and were left as they were.
- **No error text is rendered from a server message.** These five screens never
  call `messageForError`; every read is inside `Promise.allSettled` and a
  rejected read becomes `null` → the translated "unavailable" sentence. The
  only thrown error in `dashboardService.ts` ("Invoice pagination exceeded the
  safe page limit.") is internal, is swallowed by `allSettled`, and is never
  shown to a user, so it was left untranslated on purpose.
- **Data left untouched (per glossary):** patient names, MRNs, accession IDs,
  branch names, clinician names, test/panel names, result values and units,
  flag letters, waiting-time strings (`20m`), money amounts, the `—` / `·`
  separators, and the `ordered_at` short date (`20 Oct`), which is wrapped in
  `<bdi dir="ltr">` but not translated.
- **Deliberately untranslated English words** inside Urdu text: `accession(s)`,
  `critical`, `PKT`, `Asia/Karachi`, `read-only` (transliterated as ریڈ اونلی),
  `DRAFT` (→ ڈرافٹ), `API` (→ ڈیٹا/سسٹم).
