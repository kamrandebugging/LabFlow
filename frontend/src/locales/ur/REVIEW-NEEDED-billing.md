## Deliberately left in English (not defects)

- `MRN` label/value (`list.mrn_label`, `detail.mrn_value`): glossary says keep MRN.
- `Easypaisa`, `JazzCash`: brand names.
- `0.00` placeholder (`new.amount_placeholder`): numeric example, same in both locales.
- `PKR` inside `list.col_total`, `new.discount_amount_label`,
  `detail.amount_label`, `detail.refund_amount_label`: the column/field label keeps
  the currency code exactly as in English; rendered amounts use the shared
  `formatMoney` (`PKR` / `روپے`).
- Raw invoice status in the two `getStatusBadge` `default` branches: an unknown
  status is a system value, not translatable text.

## Non-translation changes made for the same screens (please sanity-check)

1. Error banners now use `messageForError(err, t)` instead of `err.message`, so
   the server's `detail` is never shown. Consequence: an unmapped server error
   shows the generic translated message instead of the old English fallbacks
   ("Failed to load invoices list", "Failed to create invoice.", etc.).
2. "Showing {n} invoices" is now one interpolated string, so the number is no
   longer bold. Same visible wording.
3. Timestamps keep the screen's existing inline formatter (`20 Oct 2026 · 10:15
PKT`, `Asia/Karachi`) wrapped in `<bdi dir="ltr">`. I did **not** switch to
   `formatDateTime` because its output is not equivalent: it drops the `PKT`
   marker and reads wall-clock fields from the wire string, which would change
   displayed times for `Z`-suffixed timestamps.
